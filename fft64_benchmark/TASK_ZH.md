# EDA Agent 挑战：设计面积与性能高效的量化 64 点 FFT 算子

## 背景

快速傅里叶变换（FFT）将一帧复数信号转换到频域。硬件 FFT 的设计不仅包含蝶形运算，还涉及运算器数量、数据存储与重排序、吞吐率、首次输出延迟及数值精度。R2SDF、R4MDC 和复用型 FFT 等架构具有不同的面积与性能权衡。对不同阶段或旋转因子选择不同精度可以节省硬件，但会影响最终输出误差。

**你的任务是设计并优化一个完整、可工作的 FFT 算子，而非只优化蝶形运算或单个算术单元。** 可以比较多种架构并选择量化策略，无需证明全局最优。

## 功能规格

- 计算 **64 点复数、正向、不归一化 FFT**：
  `X[k] = sum_{n=0}^{63} x[n] exp(-j*2*pi*n*k/64)`，`k=0..63`。
- 输入一帧 64 个复数，按自然顺序输入；输出 64 个频点，必须为**自然频率顺序**，包含必要的重排序硬件。
- 输入复数每分量为 signed 16-bit，表示 `real_int/2^15` 和 `imag_int/2^15`。
- 输入每个实部/虚部分量在 `[-0.5, 0.5]`（含边界）；所有用于评估的非零帧，其复数 RMS 不低于 `1/32`。
- 输出复数每分量为 signed 24-bit，表示 `real_int/2^15` 和 `imag_int/2^15`；不得通过后处理拟合增益、相位或输出频点顺序。

## 数值质量约束

准确参考采用**同一组已经量化后的输入**，使用 float64 计算 FFT。对每个非零输入帧定义

`SQNR(dB) = 10*log10( sum_k |X_ref[k]|^2 / sum_k |X_hw[k]-X_ref[k]|^2 )`。

每个非零测试帧必须满足 **SQNR >= 50 dB**（等价于逐帧 NMSE <= 1e-5）；全零输入帧必须输出严格为零。该指标测量**硬件实现引入的额外误差**，不将输入 ADC 量化误差再次计入。公开和隐藏有限测试不构成对所有输入的形式化保证。

## 硬件服务约束——共同服务规格

- 单同步时钟，周期 **10 ns**。
- 每帧按连续 64 个有效周期输入一个复数/周期，首样本由 `frame_start` 标记。
- 相邻帧开始时刻可以短至 **384 cycles**；也可能有更长空闲间隔。
- 每帧输出 64 个**连续有效周期**的复数，用 `out_start` 标记首频点，按自然频率顺序输出。
- 相对于首个输入时钟沿：首次有效输出**不晚于第 300 周期**，最后一次有效输出**不晚于第 364 周期**；首次输出不得早于计算所需的最后一个输入。
- 同步复位可能发生在帧前或帧处理中；复位时丢弃未完成帧，后续新帧必须正确。
- 完整设计必须在出题方统一的综合与静态时序分析流程下满足 10 ns 约束。

注意：384 cycles/frame 是本题的**服务负载**，不是对 R2SDF 最大固有吞吐的定义。默认面积模式按该服务负载比较；可选架构模式额外验证更短的声明帧间隔，见 `SCORING.md`。

## 优化目标与允许的方法

**主要目标：在全部质量/时序约束下，提高完整 FFT 的吞吐量/面积效率。** 计算逻辑、寄存器、旋转因子存储、控制、MUX、输出重排序与标准单元实现的 memory 均需计入；不存在免费 SRAM。

允许：
- R2SDF、R2^2SDF、R4SDF、R2MDC、R4MDC、复用型 radix-2/radix-4 或其他正确 FFT 架构。
- 各 stage 独立精度、truncation、round-to-nearest-even、twiddle factor 精度、guard bits、量化边界与定点 scaling。
- 不引入额外数值近似的架构/逻辑优化，例如常数旋转专用化、存储 bank、资源复用、合法重定时与流水组织。

禁止：gate-level ALS、任意近似替换/剪枝、近似 compressor，或不对应明确量化/精度变换的布尔逻辑破坏。不得改变 FFT 增益、输出顺序、时钟、输入域或 SQNR 门槛。保持数值语义的精确架构优化可以使用。

## 推荐执行流程

优先使用平台已有环境：先运行 `bash setup.sh --check-only`。默认评估会加载平台 EDA 配置并优先调用已有 VCS/DC/PrimeTime，其次复用开源工具，最后才尝试构建缺失组件；不需要先自行安装 Yosys 或 Icarus。可用 `--no-build` 禁止自动编译工具。

1. 阅读 `SPEC.json`、`ARCHITECTURE_GUIDE.md` 和 `INTERFACE.md`。
2. 参考 `DESIGN_PLAN_TEMPLATE.md` **自行创建** `DESIGN_PLAN.md`，列出至少两种可选架构与首轮实验假设。
3. 实现或修改 RTL；先获得一个精度充分、可复现的准确基线，再进行激进的精度搜索。
4. 在相同完整设计面积、数值和协议测试下比较架构；再尝试 stage-wise precision、rounding 等。
5. 每个重要实验后，更新 `DESIGN_PLAN.md` 中的实测结果、采纳/拒绝理由和下一假设，并维护简洁的 `measurements.csv`。
6. 提交满足约束、连续 PPA 得分最高的 RTL 及对应设计配置、最终设计计划。评分以出题方实测为准，不以代理自报为准。

## 通过条件与评分

- 必须同时通过数值误差、输出顺序、复位协议、服务速率、首次输出/完成延迟及静态时序约束。
- 所有约束通过即 `resolved=true`，不要求面积下降到某个比例，也不设置最低分数。
- 默认 `area` 模式：只按完整映射面积归一化。准确参考点 0 分，达到其 50% 面积为 1 分，中间连续变化。更大的可行设计也通过，但面积分为 0。
- 可选 `architecture` 模式：60% 面积、30% 已验证持续吞吐、10% 首输出延迟；在 `design_config.json` 声明 `frame_ii_cycles`（整数 64–384，默认 384），平台用连续帧及映射仿真验证。频率来自固定映射网表的 PrimeTime 时钟扫描，不是单点 slack。
- 两种模式有独立、预先冻结的标尺。SQNR 达标即可，不额外奖励更高精度。详情、公式、缓存与测量口径见 `SCORING.md`。
- RTL 必须自包含、可综合；技术库和可信综合脚本由出题方提供。
- 失败设计不能进入硬件质量排名；大量检查说明不会额外增加面积优化分数。

**最终提交：**`rtl/`、顶层 `fft64_top`、`DESIGN_PLAN.md`、`measurements.csv`，可选 `design_config.json`。不用在总结中粘贴冗长的工具日志。
